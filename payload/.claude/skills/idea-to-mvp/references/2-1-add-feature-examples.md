# 더할 기능 고르기 예시 둘 — 모양만

> **모양만 — 이 기능들을 후보로 쓰지 않는다.** 이 파일은 `2-1-mockup.md` §2.3.1대로 후보를 **다 지은 뒤에만** 연다(「예시는 모양만」 2번). 열면 지은 후보와 아래 후보가 「사용자가 하면 → 얻는 것」에서 몇 개 겹치는지 세고, 둘 이상이면 그 후보들을 그 서비스 문서에서 다시 짓는다(같은 장치 3번). 이 서비스가 아래 예시와 같은 종류면 대조를 건너뛰고 그 사실을 한 줄 적는다. 조사 에이전트에게는 넘기지 않는다.

두 예시는 지어낸 앱이다. 성격을 일부러 반대로 골랐다 — 틀은 같고 내용은 서비스마다 다르다는 것을 보이려는 것이다.

| | 예시 1 — 계산기 모음 앱 | 예시 2 — 동네 공방 수업 예약 앱 |
|---|---|---|
| 성격 | 혼자 쓰는 도구형 | 양면(수강생 · 공방 주인) · 동네형 |
| 주 사용 맥락 | 필요할 때 잠깐 열어 한 손으로 | 퇴근길 이동 중, 폰 |
| 들어오는 길 | 스토어 검색 | 동네 단골 · 지인 소개 |

## 후보 한 줄 쓰는 법 — ✗ / ✓

- ✗ 「AI 자연어 입력」 — 기술 이름이라 사용자는 무엇이 달라지는지 모른다
- ✓ 「『연봉 5천이면 실수령?』이라고 쓰면 → 맞는 계산기가 값까지 채워진 채 열린다」

## 예시 1 — 계산기 모음 앱

더하기 전 기능 목록: 분류별 목록 · 검색 · 계산기 쓰기 · 결과 복사 · 최근 쓴 계산기 · 즐겨찾기 · 운영자 계산기 추가 · 법 고지 · 기준 연도 표시.
핵심 이유(가정): 「세금·대출 계산 결과를 믿고 바로 쓰고 싶다」.

**메시지 속 후보 줄 (6개)**

*쓸 때 낫게*

1. **풀이 보기** · 변형 기능 · 크기 작음
   결과 아래 「풀이」를 누르면 → 어떤 숫자에 어떤 세율을 곱했는지 단계가 펼쳐진다
   근거: 이 서비스를 쓰는 이유(믿고 쓰기) · 사례: 조사 아님 — 핵심 이유에서
   안 고르면 → 6단계 출시 검증 뒤 다시 여쭙니다
2. **내 기본값 기억** · 흔한 기능 · 크기 작음
   연봉·부양가족 수를 한 번 넣으면 → 다른 계산기에도 그 값이 채워져 열린다
   근거: 서비스 유형(혼자 쓰는 도구형 — 자주 다시 씀) · 사례: {조사 표 3번 — 앱 이름과 스토어 링크}
   안 고르면 → 4단계 백엔드 구현 때 다시 여쭙니다(폰을 바꿔도 남으려면 로그인과 Firestore 저장이 필요)
3. **말로 묻기** · 실험 기능 · 크기 큼
   「연봉 5천이면 실수령?」이라고 쓰면 → 맞는 계산기가 값까지 채워진 채 열린다
   근거: 서비스 유형 · 사례: {조사 표 1번}
   안 고르면 → 4단계 백엔드 구현 때 다시 여쭙니다(AI 모델 API를 부르는 서버 함수가 서버 일)

*다시·새로 오게*

4. **결과 공유 그림** · 흔한 기능 · 크기 중간
   「그림으로 공유」를 누르면 → 결과 카드 그림이 폰의 공유 창에 뜨고, 단톡방에 올린 링크를 친구가 누르면 이 앱(없으면 스토어)이 열린다
   근거: 들어오는 길이 스토어 검색뿐이라 다른 길이 필요 · 사례: {조사 표 5번}
   안 고르면 → 6단계 출시 검증 뒤 다시 여쭙니다
5. **세법 바뀜 알림** · 변형 기능 · 크기 큼
   즐겨찾기한 계산기의 기준 연도가 바뀌면 → 푸시 알림으로 「다시 계산해 보세요」가 온다
   근거: 이미 있는 「기준 연도 표시」를 바꾼 것 · 사례: {조사 표 6번}
   안 고르면 → 사용자가 쌓인 뒤 다시 여쭙니다(즐겨찾기가 모여야 의미가 있음. 알림 권한과 서버 함수가 듦)
6. **자주 쓰는 계산기 바로가기** · 흔한 기능 · 크기 작음(화면 없음)
   앱 아이콘을 길게 누르면 → 자주 쓴 계산기 셋이 바로가기로 떠서 앱을 열자마자 그 계산기다
   근거: 주 사용 맥락(필요할 때 잠깐 — 찾는 걸음을 줄임) · 사례: {조사 표 7번}
   안 고르면 → 6단계 출시 검증 뒤 다시 여쭙니다

안 올린 것: 상황별 묶음(「이사할 때」 계산기 셋) — 「쓸 때 낫게」에 이미 셋 / 홈 화면 위젯 — 바로가기와 같은 방향인데 폰마다 따로 만드는 코드가 들어 크기가 큼 / 끌어서 비교 — 폰 작은 화면에서 안 맞음.

**보기 창**

1. 「쓰는 순간을 낫게 할 기능 중 이번에 더할 것을 골라 주세요.」 · 머리글 「쓸 때 낫게」 · 여러 개 고르기
   - 풀이 보기 (추천) — [변형 · 작음] 결과 아래 계산 단계가 펼쳐짐 / 안 고르면 → 6단계 출시 검증 뒤 다시 묻습니다
   - 내 기본값 기억 — [흔한 · 작음] 한 번 넣은 값이 다른 계산기에도 채워짐 / 안 고르면 → 4단계 백엔드 구현 때 다시 묻습니다
   - 말로 묻기 — [실험 · 큼] 물어보면 맞는 계산기가 값까지 채워져 열림 / 안 고르면 → 4단계 백엔드 구현 때 다시 묻습니다
   - 이번엔 고르지 않음
2. 「다시 오게·새로 들어오게 할 기능 중 이번에 더할 것을 골라 주세요.」 · 머리글 「다시·새로 오게」 · 여러 개 고르기
   - 결과 공유 그림 — [흔한 · 중간] 결과를 그림으로 올리면 친구가 링크로 들어옴 / 안 고르면 → 6단계 출시 검증 뒤 다시 묻습니다
   - 세법 바뀜 알림 — [변형 · 큼] 기준 연도가 바뀌면 푸시 알림이 옴 / 안 고르면 → 사용자가 쌓인 뒤 다시 묻습니다
   - 자주 쓰는 계산기 바로가기 — [흔한 · 작음] 앱 아이콘을 길게 누르면 자주 쓴 계산기가 뜸 / 안 고르면 → 6단계 출시 검증 뒤 다시 묻습니다
   - 이번엔 고르지 않음

답(예): 풀이 보기 · 결과 공유 그림 → `만든다` 둘, 나머지 넷은 `나중에 — {언제}`.
크기 합계 한 줄: 「더한 기능: 작음 1 · 중간 1 → 늘어나는 화면 약 1개 · 4단계 백엔드 구현 때 늘어나는 서버 일 0건 · 새 권한 0개」.

## 예시 2 — 동네 공방 수업 예약 앱

더하기 전 기능 목록: 수업 목록 · 수업 상세 · 예약 · 예약 취소 · 공방 주인 수업 등록 · 예약자 명단 · 환불 정책 고지.
핵심 이유(가정): 「퇴근 뒤 가까운 곳에서 손으로 뭔가 만들고 싶다」.

후보 줄 모양만 (4개):

- **오늘 저녁 수업만** · 변형 기능 · 작음 — 「오늘 저녁」을 누르면 → 내가 고른 동네에서 저녁 7시 넘어 시작하는 오늘 수업만 남는다(위치 권한 없이) · 근거: 핵심 이유에서 바로 · 안 고르면 → 6단계 출시 검증 뒤
- **지난 수강생 작품 모음** · 실험 기능 · 중간 — 수업 상세를 열면 → 지난 수강생이 만든 것 사진이 먼저 보인다 · 근거: 핵심 이유(손으로 만들기) — 공방 주인이 올려야 해서 반대편 역할 일이 늚 · 안 고르면 → 사용자가 쌓인 뒤
- **빈자리 나면 알림** · 흔한 기능 · 큼 — 마감된 수업에 「빈자리 알림」을 누르면 → 취소가 나올 때 푸시 알림이 온다 · 근거: 서비스 유형(예약) — 알림 권한과 서버 함수가 듦 · 안 고르면 → 4단계 백엔드 구현 때
- **친구와 같이 예약 링크** · 흔한 기능 · 중간 — 예약 뒤 「같이 가요」를 보내면 → 친구가 링크를 누를 때 이 앱(없으면 스토어)이 그 수업 화면으로 열려 옆자리로 바로 예약한다 · 근거: 들어오는 길(지인 소개) · 안 고르면 → 6단계 출시 검증 뒤

보기 창: 질문 1 「쓸 때 낫게」에 둘(오늘 저녁 · 작품 모음), 질문 2 「다시·새로 오게」에 둘(빈자리 알림 · 같이 예약), 각각 + 「이번엔 고르지 않음」.

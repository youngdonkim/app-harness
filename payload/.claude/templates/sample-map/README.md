# 견본 지도 틀

화면 목록에 **지도가 들어가는 화면**(주변 장소 찾기, 위치 고르기 등)이 있을 때, 키·가입 없이 지도를 띄우는 Flutter 부품 틀입니다. 지도가 없는 서비스는 아무것도 깔지 않습니다.

## 1. 무엇으로 그리나

- **MapLibre 공식 Flutter 플러그인 `maplibre_gl`** — 지도를 그리는 오픈소스 라이브러리 MapLibre를 폰의 진짜 지도 화면으로 띄웁니다. 플러그인(폰 기능을 쓰는 패키지)이라 iOS·안드로이드에서 각각 폰 쪽 지도 엔진이 그립니다.
- **OpenFreeMap 공개 스타일** — 지도 모양(스타일)과 지도 조각(타일)을 주는 무료 서버입니다. API 키도 가입도 없습니다. 벡터 지도(그림이 아니라 도형 정보로 받아 폰이 그리는 지도)만 주므로, 벡터 스타일을 바로 그리는 MapLibre를 씁니다.
- **쓰지 않는 것** — OpenStreetMap 공식 타일 서버(`tile.openstreetmap.org`)는 앱이 자동으로 대량 요청을 보내는 것을 정책으로 막고 있습니다. 관리가 끊긴 벡터 지도 플러그인도 쓰지 않습니다.
- **이 지도는 견본입니다** — 공개 무료 서버라 사용량 보장이 없습니다. 실서비스에서 쓸 지도(국내 지도 서비스 등 키가 필요한 것)는 4단계 준비에서 정하고, 그때 `sample_map.dart`를 갈아끼웁니다.

## 3. 넣는 차례

2-1 주요 화면 단계에서, 화면 목록에 지도가 들어가는 화면이 있을 때만 첫 화면 에이전트가 합니다(`2-1-mockup.md`의 「견본 지도」 절).

① **앱 의존성으로 깝니다** — `flutter pub add maplibre_gl`(fvm을 쓰면 앞에 `fvm`). 개발 의존성(`dev:`)이 아닙니다 — 실서비스 화면이 쓰는 패키지라서입니다. 판은 그때의 최신 stable이고, 고른 판은 `pubspec.lock`이 기록합니다.

② **폰 쪽 준비를 패키지 문서대로 합니다** — 패키지 README의 「요구 사항」과 시작 안내(getting started)를 읽고 따릅니다. 이 부품은 사용자 위치를 쓰지 않으므로 위치 권한 설정은 하지 않습니다.

- **iOS** — 첫 빌드 때 Xcode가 지도 엔진을 Swift Package Manager(Xcode의 패키지 관리 도구)로 내려받습니다. 몇 분 걸립니다. 패키지가 요구하는 최소 iOS 판이 프로젝트 설정보다 높으면 프로젝트 설정을 올립니다.
- **안드로이드** — 패키지가 요구하는 자바(JDK) 판과 최소 안드로이드 판을 확인합니다. **CI(`.github/workflows/ci.yml`)의 디버그 빌드가 쓰는 자바 판도 같이 맞춥니다** — 다르면 내 컴퓨터에서는 되고 CI 빌드만 실패합니다.

③ **부품을 놓습니다** — `sample_map.dart.template`을 `lib/shared/components/common/sample_map.dart`로 복사합니다. `test/`의 파일에서 `package:<앱>/`을 앱 패키지 이름으로 바꿔 복사합니다.

- **지도 칸에는 크기가 꼭 있어야 합니다** — 지도는 받은 자리를 꽉 채웁니다. `Column` 안에서는 `Expanded`로 감싸 남은 자리를 주고, 높이를 숫자로 박지 않습니다(디자인 규칙 검사 1번).
- **점 색·크기는 토큰에서 옵니다** — 부품이 `context.colors.primary`·`context.space`를 읽어 지도 라이브러리가 받는 꼴(`'#RRGGBB'` 글자)로 바꿔 넘깁니다. 색을 바꾸려면 2층 값을 바꿉니다.
- **오른쪽 아래 출처 표시(i 단추 — OpenFreeMap · OpenMapTiles · OpenStreetMap)는 지도 사용 조건입니다.** 숨기지 않습니다.
- **좌표는 위도·경도 순서입니다** — `(lat: 37.5665, lng: 126.9780)`처럼 적습니다. 웹 지도 라이브러리에서 흔한 `[경도, 위도]` 순서와 반대입니다.
- **점을 눌렀을 때 할 일은 화면이 정합니다** — `onMarkerTap`으로 받은 장소의 이름을 띄울지, 상세 화면으로 갈지 화면 코드가 고릅니다. 부품 안에는 화면에 보이는 글자가 없습니다.

④ **견본 장소 데이터를 저장·조회 코드에 둡니다** — 장소 이름과 좌표는 예시 콘텐츠처럼 그럴듯하게 지어서 그 흐름의 가짜 저장소(`lib/dev/fakes/`)와 기기 안 저장소의 견본 데이터에 넣습니다. 화면에 박지 않습니다.

- **주소 검색은 「견본 장소 목록에서 찾기」로 흉내 냅니다** — 입력한 글자로 견본 장소의 이름·주소를 걸러 보이는 것입니다.
- **공개 주소 검색 서비스(Nominatim)는 부르지 않습니다** — 초당 1회 제한과 자동완성 금지가 정책이라, 글자를 칠 때마다 부르는 화면이 금지에 걸립니다. 진짜 주소 검색은 실서비스 지도를 정하는 4단계 준비에서 함께 정합니다.

⑤ **설계 결정 기록(ADR — `mvp/adr.md`)에 한 줄 적습니다** — 「지도는 지금 견본 지도(OpenFreeMap, 키 없음). 실서비스 지도 교체는 4단계 준비에서 정한다.」

⑥ **확인합니다** — `flutter analyze`, `dart analyze`(Riverpod 린트는 이쪽에서만 돕니다), `flutter test --exclude-tags golden`, iOS 시뮬레이터용 빌드(`.claude/scripts/build-lock.sh flutter build ios --simulator --debug -t lib/main_dev.dart`)와 안드로이드 디버그 빌드(같은 잠금을 앞에 붙임). 지도가 실제로 뜨는지, 점과 출처 표시가 보이는지, 지명이 한글로 나오는지는 사람이 시뮬레이터·폰·목업 캔버스에서 봅니다.

## 4. 알아 둘 것

- **테스트 안에서는 지도 대신 빈 자리가 그려집니다** — 지도는 폰의 진짜 지도 화면(플랫폼 뷰 — Flutter 화면 안에 폰 쪽 화면을 끼워 넣는 장치)이라 `flutter test`에서는 그려지지 않습니다. 부품이 테스트 안인지 스스로 알아채고 같은 크기의 빈 자리(지도 아이콘)를 그립니다. 그래서 목업 캔버스의 미리보기 그림(골든 그림)에서도 지도 칸은 빈 자리로 나옵니다. 지도는 캔버스를 확대해 실제 화면으로 바뀐 창에서 봅니다.
- **지명은 한글 우선입니다** — 부품이 처음 한 번 스타일 문서를 받아, 지명을 읽는 글자 층마다 「한국어 이름(`name:ko`) → 원래 이름(`name`)」 순서로 읽게 고쳐서 씁니다. 지명이 영어로 나오면 스타일 문서를 받지 못한 것입니다 — 그때 부품은 원래 주소로 지도를 띄우고, 디버그 출력에 「견본 지도: 스타일을 받지 못해 원래 주소로 씁니다」를 남깁니다.
- **목업 캔버스는 지도 화면의 창을 여러 개 띄웁니다** — 실제 화면으로 바뀐 창마다 지도 엔진이 하나씩 뜹니다. 캔버스가 실제 화면을 동시에 8개까지만 띄우므로 그 이상은 늘지 않습니다.
- **지도는 `?state=`를 모릅니다** — 빈·로딩·오류 상태의 지도 칸은 저장·조회 코드가 주는 결과(빈 장소 목록 등)로 화면이 그립니다.
- **장소 목록을 바꾸면 점을 다시 찍습니다** — 부품은 목록이 다른 `List`로 바뀌었을 때만 점을 다시 찍습니다. 같은 목록을 고쳐 쓰지 말고 새 목록을 넘깁니다.

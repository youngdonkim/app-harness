# 참고 디자인에서 스타일 값 뽑기

참고 앱 캡처·사이트·색 값·프리셋에서 색·서체·둥글기 같은 값과 버튼·카드 같은 부품의 모양을 뽑아, 1·2층 토큰과 3층 부품(감싸개·Material 부품 테마)의 출발값으로 삼는 방법이다. 고르는 법 → 값 뽑는 법 → 분석 항목표 → 토큰에 잇는 법 → 금지 차례로 읽는다.

## 1. 이 문서를 언제 쓰나

- **참고에서 값을 뽑을 때** — idea-to-mvp 1단계 인터뷰(`1-intent.md` §2.1 5번·§2.4)에서 참고 디자인을 받아 브리프에 적을 때, 2단계에서 참고를 더 받을 때(`2-1-mockup.md` §2.2), 이미 지은 프로젝트의 브랜드를 바꿀 때(리브랜딩).
- **뽑아 둔 값을 토큰으로 옮길 때** — 브리프 「4. 확정 브랜드 자산」의 「우리가 쓰는 값」 표를 1층 상수(`foundation.dart`)·2층 역할 이름(`semantic.dart`)으로 옮길 때 (§5). idea-to-mvp에서는 2단계 개발환경 준비의 디자인 시스템 첫 세팅(`2-0-dev-setup.md` §2.5)이 이 자리다.

참고를 읽는 일이지 우리 화면을 판정하는 일이 아니다 — 남의 사이트를 브라우저로 열어도 「화면 검증은 사람 몫」 원칙과 부딪히지 않는다. 우리 앱은 폰 앱이지만 참고는 웹사이트여도 된다 — 색·서체는 웹에서 정확히 읽히고, 부품 모양은 앱 캡처가 더 잘 맞는다(§2).

**값의 정본** — 뽑은 값은 사람이 읽는 형식(hex·서체 이름·크기 숫자·말)으로 적는 **출발값**이다. 1층 상수로 옮긴 뒤부터 정본은 1층(`foundation.dart`)이고, 화면 코드는 2층 이름(`context.*`)만 쓴다 (SKILL.md 철칙). 기록 자리는 프로젝트가 정한다 — idea-to-mvp 프로젝트면 `mvp/design-brief.md` 「4. 확정 브랜드 자산」의 두 표(「우리가 쓰는 값」·「참고 기록」)다.

## 2. 고르는 법

**셋만 지킨다.**

- **같은 유형에서 고른다** — 유형은 [common-patterns.md](common-patterns.md) §1.1 유형표의 유형(SaaS · 커머스 · 마켓플레이스 · O2O · 커뮤니티 · SNS · 사람 매칭 · 혼자 쓰는 기록·도구형)이다. 쇼핑몰에 회사 소개 사이트를 참고하면 구성이 안 맞는다. 다른 유형의 사이트를 「구성」 축으로 고르면 한 번 짚는다 — 그래도 원하면 사용자 결정이 이긴다 (common-patterns.md §1 머리).
- **닮을 축을 정한다** — 색 · 부품 모양 · 글자 · 밀도 · 구성 · 움직임 중 그 참고에서 닮을 것. 참고 하나가 여러 축을 맡아도 된다. 대신 축마다 출처는 하나다 — 두 참고가 같은 축을 잡으면 하나를 고르게 한다.
- **1~3개** — 많을수록 섞여 흐려진다. 상반된 것(예: 촘촘한 표 화면 + 여백 큰 소개 화면)은 같이 고르지 않는다.

**사용자가 참고를 주지 않았거나 모자라면 AI가 추천한다** — 참고가 없거나 닮을 축 일부만 덮을 때(idea-to-mvp 1단계 인터뷰 5번이 이 경우다), 위 셋을 지켜 같은 유형의 실제 사이트 2~3곳을 골라 곳마다 닮을 축을 한두 개씩 붙여 추천하고 사용자가 고르게 한다. 추천은 사용자가 준 참고가 덮지 않은 축만 채운다 — 준 참고가 먼저다. 사용자에게는 축을 쉬운 말로 보여 준다(색 · 글씨 · 모양 = 버튼·카드·입력칸·메뉴의 생김새와 둥글기·그림자 · 빽빽한 정도 · 구성 = 첫 화면 차례 · 움직임). 고른 사이트는 아래 §3의 사이트 주소 갈래로 분석한다. 앱을 추천할 때는 스토어 링크로 내고, 곳마다 몇 번째 스크린샷의 무엇을 닮을지 붙인다(§3의 스토어 링크 갈래).

**우리 제품은 폰 앱이라, 「부품 모양」·「밀도」·「구성」 축은 앱 화면 캡처를 먼저 권한다** — 웹사이트, 특히 앱 소개 페이지에는 카드·입력칸·하단 탭 같은 앱 부품이 없거나 컴퓨터 폭으로 펼쳐져 있어 폰 한 화면의 모양을 읽기 어렵다. 그래서 Mobbin 같은 앱 캡처 갤러리(아래 표)나 사용자가 폰에서 찍은 캡처를 먼저 권하고, 웹사이트를 고른다면 닮을 축을 색 · 글씨로만 맡긴다.

**갤러리는 고르는 곳이지 입력이 아니다** — 사용자가 갤러리에서 골라 §3의 다섯 입력 중 하나로 넘긴다. 문서에는 최상위 주소만 둔다. 유형별 분류 주소는 사이트 구조가 자주 바뀌니, 필요할 때 그 사이트에서 찾아 짚어 준다 (바깥 사이트를 여는 일이라 §3 재시도 한도를 따른다).

| 갤러리 | 주소 | 로그인·유료 | 무엇을 보나 | 넘기는 법 |
|---|---|---|---|---|
| Mobbin | https://mobbin.com | 로그인 필요, 많이 보려면 유료 | 실제 앱 화면을 앱·화면 종류별로 모은 곳. 같은 업종 앱의 첫 화면·목록 화면 | AI는 열지 않는다 — 사용자가 캡처해 이미지로 |

## 3. 입력 다섯 종류와 값 뽑는 법

| 입력 | 하는 일 | 정확도 |
|---|---|---|
| 사이트 주소 | 브라우저 도구로 열어 계산된 스타일(브라우저가 실제로 적용한 웹 스타일 값)을 읽고, 같은 세션에서 화면 한 장으로 느낌을 본다 (아래) | 색·서체 이름·둥글기·그림자는 정확. 부품 모양은 스타일과 화면을 같이 보면 정확. 어느 요소가 강조색인지는 판단이 든다 |
| 스토어 링크(구글 플레이·앱스토어 앱 소개 페이지) | 메인이 내장 브라우저로 페이지를 열고 스크린샷 이미지 주소(구글 플레이는 `play-lh.googleusercontent.com`, 끝의 `=w240-h480-rw` 같은 크기 지정을 `=w1080` 등으로 바꾸면 큰 원본)를 읽어 이미지를 직접 본다. 그 뒤는 스크린샷·이미지와 같다 (아래) | 부품 모양·밀도·구성은 잘 본다. 스토어 스크린샷은 광고용이라 위에 홍보 글귀가 얹혀 있고 실제 화면보다 줄어 있어, 색은 눈대중이고 글귀 자리는 읽지 않는다 |
| 스크린샷·이미지(앱 캡처 포함) | 화면을 보고 값을 눈대중한다. 폰 캡처는 기기 화면 배율(대개 2~3배)로 나눠 dp로 적는다 | 색은 압축·색 공간 탓에 어긋나고 서체 이름은 맞히기 어렵다. 부품 모양·밀도·구성은 잘 본다 |
| 색 값 | 받은 hex를 그대로 적는다 | 정확 |
| 프리셋 | 그 프리셋이 정한 색 값을 그대로 옮긴다. oklch면 hex로 바꾸고 괄호에 원값 | 정확 |

**누가 뽑아도 사용자가 직접 준 값(색 값·서체 이름)이 이긴다.**

**사이트 주소 — 값은 계산된 스타일로, 느낌은 화면 한 장으로**

- 실제 적용된 CSS 값을 요소별로 읽는다 — body 배경색(배경) · 본문 글자색(글자) · 주 버튼이나 링크의 배경색(강조) · 성공·위험 표시가 보이면 그 색 · 제목과 본문의 `font-family` · 카드와 버튼의 `border-radius` · 카드의 `box-shadow` · `:root`에 선언된 CSS 변수(이름에 primary·brand가 들어간 것). 화면에 없는 값(예: 첫 화면에 위험 표시가 없음)은 지어내지 않고 「관찰 못 함」으로 적는다.
- **주 행동이 그림이라 버튼 색이 없으면** — 예: 주 행동이 앱 내려받기 배지(그림)뿐인 소개 페이지. 강조는 `:root`에 선언된 팔레트 변수에서 후보를 고르고, 뽑은 값 끝에 「(주 버튼 색 없음 — `:root` 팔레트에서 고름)」이라고 적는다. **`:root`에도 팔레트가 없으면** 링크 글자색 같은 엉뚱한 색을 고르지 않고, 강조는 「관찰 못 함」으로 적은 뒤 §4 끝의 AI 제안 값으로 채운다.
- **다른 회사가 끼워 넣은 부분에서는 값을 읽지 않는다** — 쿠키 안내 띠·채팅 창·결제 창·광고처럼 사이트 주인이 아니라 외부 서비스가 끼워 넣은 요소의 색·글씨·모양은 그 사이트의 디자인이 아니다. 성공·위험 색이나 버튼 색을 이런 요소에서 읽지 않고, 그 사이트 자체 화면에서 못 찾으면 「관찰 못 함」으로 둔다.
- 부품 모양은 스타일과 화면을 같이 본다 — 주 버튼과 보조 버튼의 배경·`border`·높이, 카드의 `box-shadow`·`border`·body와의 배경색 차이, 입력칸의 `border`(네 변인지 아래만인지)·배경, 메뉴가 화면 아래에 고정된 탭바인지(`position: fixed; bottom`) 상단 탭인지 햄버거 버튼(줄 세 개를 누르면 메뉴가 펼쳐지는 버튼)인지. 결과는 말로 적고 읽은 px를 덧붙인다.
- 같은 세션에서 화면 한 장을 찍어 밀도·첫 화면 구성을 본다. 한 번 열 때 둘 다 하면 추가 비용이 거의 없다.
- **연 조건을 값과 함께 적는다** — 라이트·다크, 창 폭. 운영체제 다크 모드·A/B 실험(사람마다 다른 화면을 보여 주는 실험)·로그인 전후에 따라 다른 값이 나온다.
- 브라우저 출력이 맥락을 많이 먹으니 서브 에이전트에 맡기는 게 맞다. 지시서에 아래 재시도 한도 줄·로그인 멈춤 줄·「재위임 금지」 줄을 넣고, 「쿠키 안내 띠·채팅 창처럼 다른 회사가 끼워 넣은 요소에서는 값을 읽지 마라」 줄도 넣는다.

**실패 모드**

| 실패 | 대응 |
|---|---|
| 로그인 벽 (Mobbin 등) | 열지 않는다. 로그인 화면이 뜨면 1회에 멈추고 사람에게 — 그 화면 스크린샷을 받아 이미지 갈래로 |
| 사용자가 말한 축(예: 색)이 공개 첫 화면에서 안 보임 | 그 축이 로그인 뒤 화면에만 있을 수 있다 — 지어내지 않고 사용자에게 그 화면 캡처를 한 번 부탁해 이미지 갈래로 뽑는다. 부탁은 한 번뿐이고, 못 받으면 그 축은 「관찰 못 함」으로 두고 AI 제안 값(§4 끝)으로 채운다 |
| 동적 테마 | 연 조건(라이트·다크, 폭)을 함께 적는다 |
| 서체 라이선스 | 이름은 정확히 나오지만 전용·유료 서체가 많다 → 무료 대체 (§6) |
| 봇 차단·캡차(CAPTCHA — 사람인지 확인하는 퍼즐) | 우회하지 않고 멈춘다 |
| 그림으로만 그린 화면(이미지·`<canvas>` 요소) | CSS에 값이 없다 → 화면 한 장으로 눈대중하고 표시를 붙인다 |

**재시도 한도** — 바깥 사이트를 여는 일이라 적용한다. 같은 실패 2회면 멈추고 보고한다. 401·403·404는 다시 하지 않는다. 로그인 화면이 뜨면 1회에 멈추고 사람에게 넘긴다. 반복된 실패 시도는 계정 제재로 이어진다.

**눈대중 표시** — 이미지에서(또는 CSS 값이 없어 화면에서) 뽑은 값은 「뽑은 값」 끝에 「(화면에서 눈대중)」을 붙인다. 이 표시가 빠지면 추정값이 확정처럼 전달된다 — 토큰으로 옮길 때 사람이 한 번 더 볼 표시다.

## 4. 분석 항목표

참고를 이 아홉 항목으로 나눈다. 참고마다 닮을 축이 덮는 항목만 채운다.

| 닮을 축 | 덮는 항목 |
|---|---|
| 색 | 색 다섯 |
| 글자 | 서체 둘 |
| 부품 모양 | 둥글기 · 그림자 · 부품 모양 |
| 밀도 | 간격 · 밀도 |
| 구성 | 첫 화면 구성 |
| 움직임 | 움직임 느낌 |

| 항목 | 무엇을 적나 | 적는 형식 | 예 |
|---|---|---|---|
| 색 — 배경·글자·강조·성공·위험 | 역할마다 한 색 | hex(`#3182F6`처럼 16진수 여섯 자리 색 코드 — 코드로 옮기면 `Color(0xFF3182F6)`). 원래 oklch면 괄호에 원값 | 강조 `#3182F6` · 배경 `#FFFFFF` |
| 서체 — 제목·본문 | 서체 이름과 라이선스 | 이름 + 무료/유료, 유료·전용이면 대체 이름 | 「본문: Pretendard(무료)」「제목: ○○ Sans(전용) → Pretendard Bold로 대체」 |
| 둥글기 | 카드와 버튼의 모서리 | 숫자 두 개(웹에서 읽은 px는 앱의 dp와 같은 크기로 본다) | 「카드 16px · 버튼 10px」 |
| 간격 | 요소 사이 여유 | 「촘촘 · 보통 · 넉넉」 중 하나 + 관찰 예 | 「보통 — 카드 안 여백 약 20px」 |
| 그림자 | 카드·떠 있는 요소의 입체감 | 「없음 · 옅음 · 뚜렷」 + 관찰값 한 줄(있으면) | 「옅음 — 아래로 2px, 넓게 퍼진 연한 회색」 |
| 밀도 | 한 화면에 담기는 양 | 말 한 줄 | 「첫 화면에 목록 10건 이상, 본문 15px」 |
| 첫 화면 구성 | 최상단부터의 차례 | 문장 — 브리프 「5. UI 패턴 지정」에 「첫 화면: …(참고 1, 이유)」 | 「검색 → 카테고리 → 목록 (참고 1, 바로 고르게)」 |
| 움직임 느낌 | 무엇이 어떻게 움직이는지 | 말만 — 브리프 「8. 모션·인터랙션 방향」의 「참고 사이트」 행 | 「카드가 아래에서 순서대로 올라옴」 |
| 부품 모양 | 버튼·카드·입력칸·상단 메뉴와 탭의 생김새 | 부품마다 말 한 줄. 관찰한 px가 있으면 덧붙임 | 「버튼: 테두리만, 높이 낮음(약 36px) · 카드: 그림자 없이 선으로 나뉨 · 입력칸: 밑줄 · 메뉴: 아래 고정 탭바」 |

**부품 모양에서 고르는 말** — 버튼은 꽉 찬 색 · 테두리만 · 글자만, 카드는 그림자로 뜸 · 선으로 나뉨 · 배경색 차이, 입력칸은 테두리 상자 · 밑줄 · 채운 배경, 상단 메뉴와 탭은 아래 고정 탭바 · 상단 탭 · 햄버거 메뉴 중에서 고른다. 어느 것에도 안 맞으면 본 대로 적는다. 모서리 둥글기와 그림자 값은 각자 행에 적고, 여기에는 생김새만 적는다.

**「바꾸고 싶은 것」이 밝기를 뒤집으면** — 예: 어두운 참고에 「밝게」. 참고의 밝은 색을 배경으로, 진한 색을 글자·강조로 옮긴다. 옮긴 짝은 대비를 다시 잰다(배경 위 글자·강조 위 글자 모두 4.5:1 이상, §5). 참고에서 잰 대비는 뒤집은 짝에 그대로 맞지 않는다.

**제안 스타일 한 벌 짓기** — 참고가 없거나 참고가 덮지 않은 축이 있으면, AI가 서비스 유형과 브리프 「1. 브랜드 인상과 관점」의 브랜드 인상 한 줄을 보고 같은 형식으로 채운다.

- **값이 있는 여섯을 값까지** — 색 다섯 · 서체 둘 · 둥글기 · 간격 · 그림자 · 밀도. 말 한 줄(「밝고 둥글게」)로 두면 화면을 그리는 쪽이 빈 곳을 제멋대로 채운다.
- **부품 모양도 채운다** — 버튼·카드·입력칸은 Material 3 기본 모양을 말로 적는다(예: 「버튼 꽉 찬 색 · 카드 옅은 바탕색 차이 · 입력칸 테두리 상자」). 테마 값만 바꾸면 되는 모양이라 옮기는 일이 가장 적다. 이동 구조는 브리프 「6. 주 사용 맥락」을 따른다 — 자주 오가는 최상위 화면이 셋 이상이면 아래 고정 탭바, 아니면 상단 바만.
- 첫 화면 구성은 common-patterns.md §1 유형 기본값을 따르니 따로 적지 않는다. 움직임은 브리프 「8」의 기본값 그대로 둔다.
- 서체는 무료 서체로 고른다. 글자색은 배경과 4.5:1 이상이어야 하고, 강조색 위 글자도 4.5:1을 넘게 고른다(§5).
- 밀도는 유형을 따른다 — 훑는 화면은 촘촘하게, 읽는 화면은 넉넉하게 (common-patterns.md §1.2).
- 브리프 「7. 피할 것」(예: 보라 그라데이션류)에 걸리는 값은 고르지 않는다.
- 실제 서비스 이름을 붙이지 않는다 — 사용자가 그 서비스를 참고로 오해해 복제 쪽으로 끌린다.
- 지위는 `가정`이다. 사용자가 화면을 보고 괜찮다고 하면 `사용자 확정`으로 올린다.

## 5. 분석값 → 토큰

브리프의 값을 1층 상수(`foundation.dart`)와 2층 역할 이름(`semantic.dart`)으로 옮기는 대응이다. 파일 모양은 [bootstrap-project.md](bootstrap-project.md) §1.2, 이름 문법은 [naming-taxonomy.md](naming-taxonomy.md) §2 유형표를 따른다.

| 분석 항목 | 1층 (기본 값) | 2층 (역할 이름) |
|---|---|---|
| 색 — 배경 | 회색 램프의 가장 밝은 단계(`Palette.gray0` 류) | `surface`. 표면 계단(`surfaceContainerLow`·`surfaceContainer`·`surfaceContainerHigh`)은 같은 램프 이웃 단계 |
| 색 — 글자 | 회색 램프 진한 쪽(`Palette.gray900` 류) | `onSurface`. `onSurfaceVariant`·`subtle`은 같은 램프에서 파생하고 바탕과 4.5:1 |
| 색 — 강조 | 그 색을 600 근처에 둔 브랜드 램프 50~950 | `primary`·`onPrimary`. 옅은 단계는 `primaryContainer`·`onPrimaryContainer` |
| 색 — 성공 | 초록 램프 | `success`·`onSuccess` — Material 세트에 없어 더한다 (naming-taxonomy.md §2 color/semantic 행) |
| 색 — 위험 | 빨강 램프 | `error`·`onError`. 장식에 쓰지 않는다 |
| 색 — 브랜드 면 | 강조색 램프의 옅은 쪽 또는 아주 진한(900~950) 단계, 두 번째 색이면 그 색의 램프를 새로. 바탕과 1.2:1 이상, 2층에 이미 이어진 상태 단계(선택된 것 바탕 등)는 피한다 (SKILL.md 「브랜드 색은 어디에 쓰나」) | `AppBrand`의 `surface`·`onSurface` — Material 세트에 없어 별도 확장으로 더한다 (naming-taxonomy.md §2 color/brand 행). 넓은 면에만 쓴다. 참고에서 뽑지 않고 idea-to-mvp 2-3이 비교안으로 정한다 |
| 서체 — 제목·본문 | 서체 이름(`FoundationType.family`)과 앱에 넣는 서체 파일. 넣는 법은 [font-loading.md](font-loading.md) | `AppTextStyles`의 각 단계 `fontFamily`. 제목 서체가 다르면 `t1`~`h3`만 다른 서체 이름 |
| 둥글기 | `FoundationRadius.base` = 카드 값 | `AppRadius.card`는 `base`, `control`은 `base`에서 뺀 값 — 버튼 값이 나오게 차이를 고른다 (SKILL.md 동심원 radius 규칙) |
| 간격 | 4 단위 격자(`FoundationSpace.unit`)는 그대로 둔다 | 따로 이름 없음 — 화면 좌우 여백(`AppLayout.screenX`)과 부품 안쪽 여백 단계를 고르는 근거. adapter 적용 규칙 요약에 한 줄 ([bootstrap-project.md](bootstrap-project.md) §4) |
| 그림자 | 그림자 원본(`FoundationShadow`) | `AppShadows.card` 등 (naming-taxonomy.md §2 shadow 행). Material 부품은 그림자 대신 표면 계단으로 깊이를 내는 쪽이 기본 |
| 밀도 | 글자 크기 원본의 본문 크기(`FoundationType.b1`) | `context.text.b1`. 화면 단위 조정이 필요하면 naming-taxonomy.md §2의 「화면·묶음 단위로 토큰을 비례 조정할 때」 |
| 첫 화면 구성 | 토큰 아님 | 토큰 아님 — `feature-list.md` 화면 목록의 홈 행이 받는다 |
| 움직임 느낌 | 말로 적은 느낌을 움직임 값으로 바꿀 때 만든다 (idea-to-mvp는 3단계 `3-frontend-build.md`의 모션·마이크로 인터랙션 다듬기 절) | `AppMotion`의 `fast`·`base`·`slow`·`standard`·`emphasis` ([bootstrap-project.md](bootstrap-project.md) §1.4) |
| 부품 모양 | 토큰 아님 | 토큰 아님 — 3층 부품의 기본 모양으로 간다 (아래) |

**부품 모양 → 3층 부품** — 버튼·카드·입력칸은 `theme.dart`의 Material 부품 테마와 감싸개(`AppButton`·`AppTextField`)가, 상단 바와 하단 탭은 셸과 그 부품 테마(`appBarTheme`·`navigationBarTheme`)가 받는다. 예: 「버튼 테두리만」이면 주 버튼이 아닌 버튼의 기본을 테두리형(`secondary`)으로 두고, 「입력칸 밑줄」이면 `inputDecorationTheme`의 테두리를 밑줄형으로 바꾼다. 고치는 차례(2층 값 → variant → 감싸개 파일)와 기록은 [component-taxonomy.md](component-taxonomy.md) §4.1을 따른다. 둥글기·그림자는 위 표대로 2층 값이 먼저 맞춘다.

**강조색 하나에서 브랜드 램프 50~950 만들기**

1. hex를 oklch로 바꾼다 — L(밝기)·C(채도)·H(색상) 세 값이 나온다.
2. **H는 고정**하고 단계마다 **L만 바꾼다** — 50이 가장 밝고 950이 가장 어둡다. C는 양 끝(50·950)에서 줄인다. 양 끝에서도 채도를 그대로 두면 색이 탁하거나 형광처럼 뜬다.
3. 원래 색은 600 근처에 둔다. 원래 색의 밝기가 600 자리에 비해 너무 밝거나 어두우면, 그 밝기에 가까운 단계에 둔다 — 원래 값을 억지로 600에 맞추지 않는다.
4. 다 만든 단계는 `Palette.brand50`~`Palette.brand950`에 `Color(0xFF…)`로 적는다.
5. 이미 채택한 1층 램프가 있으면 새로 만들지 않고 가장 가까운 단계에 맞춘다 — 단계를 새로 만들지 않는다.

**`on` 짝 대비 확인** — `primary` 위 `onPrimary`, `surface` 위 `onSurface`·`onSurfaceVariant`·`subtle`이 모두 4.5:1 이상이어야 한다. 손으로 재지 않고 대비 계산 도우미(`contrastRatio`)와 대비 테스트가 잰다([bootstrap-project.md](bootstrap-project.md) §1.5). 강조색이 밝아 흰 글자가 4.5:1에 못 미치면 `primary`를 한 단계 진한 쪽(700)으로 잇거나 글자를 진한 색으로 바꾼다. 브리프 값을 고치는 게 아니라 잇는 단계를 고르는 일이다.

## 6. 금지

- **통째 복제 금지** — 참고 화면을 그대로 베끼지 않는다. 요소의 위치·크기를 그대로 옮기지 않고, 로고·그림·사진·문구를 가져오지 않는다. 뽑는 건 값(색·서체 이름·px), 말로 적은 느낌, 그리고 「구성」 축이면 화면 위에서 아래로 놓인 차례(예: 검색 → 카테고리 → 목록)뿐이다. 문구·말투는 보이스 앤 톤으로 들어오지 않는다.
- **유료·전용 서체는 무료 대체** — 같은 계열(고딕·명조 등)이고 굵기 폭이 비슷한 무료 서체를 고른다. 원래 이름과 대체 이름을 같이 적는다.
- **섞어 평균 내지 않는다** — 축마다 출처 하나. 두 사이트의 강조색을 섞어 중간색을 만들지 않는다.
- **로그인이 필요한 화면은 열지 않는다** — 사람이 캡처해 이미지로 준다.
- **눈대중 값을 확정처럼 적지 않는다** — 「(화면에서 눈대중)」 표시를 붙인다 (§3).

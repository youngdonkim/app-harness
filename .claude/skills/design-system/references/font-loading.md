# 한글 서체 넣기 (앱)

한글 서체를 Flutter 앱에 넣는 방법. 웹처럼 「필요한 조각만 그때그때 받아 오기」가 앱에는 없다 — 서체 파일은 앱 설치 파일 안에 함께 들어가고, 앱은 첫 실행부터 그 파일로 그린다. 그래서 문제는 「얼마나 빨리 받나」가 아니라 **「앱 크기를 얼마나 늘리나」와 「모든 글자가 그 서체로 나오나」**다.

## 1. 원리 — 서체는 앱 안에 넣는다

- 서체 파일(`.ttf`·`.otf`)을 저장소의 `assets/fonts/`에 두고 `pubspec.yaml`에 등록하면, 빌드할 때 앱 설치 파일 안에 들어간다.
- 앱은 기기에 있는 그 파일로 바로 그린다. 그래서 첫 실행·비행기 모드에서도 글자 모양이 같고, 글자가 다른 서체로 보였다가 바뀌는 깜빡임이 없다.
- 대신 서체 파일 크기만큼 앱이 커진다. 한글은 글자가 1만 자가 넘어 서체 하나가 MB 단위다. 그래서 **쓰는 굵기만 넣고, 가변 서체가 있으면 그것 하나를 넣는 것**이 크기 관리의 전부다.

## 2. google_fonts 패키지를 쓰지 않는 이유

`google_fonts`는 앱이 실행 중에 인터넷으로 서체를 받아 오는 패키지다. 이 하네스는 쓰지 않는다.

- **첫 실행·오프라인에서 글자가 바뀌어 보인다** — 받기 전에는 기기 기본 서체로 그렸다가, 받고 나면 바꿔 그린다. 글자 폭이 달라 줄바꿈이 바뀌고 화면이 한 번 들썩인다.
- **사람이 화면을 보는 상황이 매번 다르다** — 같은 화면이 네트워크 상태에 따라 다르게 보이면, 목업 캔버스와 폰에서 본 것이 어긋난다.
- **골든 테스트(화면을 그림으로 찍어 비교하는 테스트)가 흔들린다** — 테스트 환경에서 서체를 받지 못하면 그림이 기본 서체로 찍힌다.

구글 서체를 쓰고 싶으면 그 서체 파일을 내려받아 §4대로 앱에 넣는다(구글 서체는 대부분 자유 이용 허가라 넣어도 된다 — 서체마다 허가 문서를 확인한다).

## 3. 토큰 계층에서의 자리

- 서체 이름은 **foundation(1층) 기본 값**이다. 색 램프와 같은 자리다 — `foundation.dart`의 `FoundationType.family`(제목 서체가 따로 있으면 `FoundationType.titleFamily`). 값은 `pubspec.yaml`의 `family` 이름과 글자 하나까지 같아야 한다.
- **2층 `AppTextStyles`의 각 글자 단계가 이 이름을 `fontFamily`로 쓴다.** `theme.dart`는 `ThemeData.fontFamily`에도 같은 이름을 넣어, Material 부품의 글자도 같은 서체로 나오게 한다.
- 제품 코드는 `context.text.*`만 쓴다. 그래서 서체를 통째로 갈아끼워도 1층과 `pubspec.yaml`만 바뀌고 화면 코드는 한 줄도 안 바뀐다.
- **어떤 파일을 넣을지는 토큰이 아니다** — 파일 목록은 `pubspec.yaml`의 일이다. 토큰 파일에 파일 경로를 적지 않는다.

## 4. 넣는 방법

### 4.1 파일 고르기 — 가변 서체냐 굵기별 파일이냐

| 서체가 주는 것 | 넣는 것 | 메모 |
|---|---|---|
| 가변 서체(굵기를 한 파일 안에서 연속으로 바꾸는 서체) | 그 파일 하나 | 굵기를 몇 개 쓰든 파일 하나라 대개 가장 작다. 지금 Flutter stable에서는 `FontWeight`가 가변 서체의 굵기 축까지 정한다(Flutter 공식 breaking change 문서 「FontWeight also controls the weight attribute of variable fonts」). 프로젝트의 Flutter 판이 그보다 옛것이면 `FontVariation.weight`를 따로 줘야 하니, 도입 때 판을 확인한다 |
| 굵기별 파일만 | 쓰는 굵기만(대개 400·500·700 세 개) | 안 쓰는 굵기는 넣지 않는다. 넣지 않은 굵기를 쓰면 Flutter가 가까운 파일을 억지로 두껍게·얇게 흉내 내 모양이 어색해진다 |
| 웹 전용 형식(`.woff`·`.woff2`)만 | 넣지 않는다 | 앱 서체는 `.ttf`·`.otf`로 넣는다. 같은 서체의 `.ttf`·`.otf` 배포본을 찾는다 |

- **유료·전용 서체는 쓰지 않고 무료 대체를 고른다** ([reference-analysis.md](reference-analysis.md) §6). 앱에 넣는 것은 재배포라, 무료 서체라도 허가 문서에서 「앱에 넣어 배포」가 되는지 확인한다(대부분의 자유 서체 허가 SIL OFL은 된다).
- **가변 서체와 굵기별 파일 중 무엇이 작은지는 재 본다** — 서체마다 다르다. 둘 다 받아 크기를 비교하고 작은 쪽을 고른다.

### 4.2 한글 글자를 줄이지 않는다

웹에서는 서체를 조각으로 나눠 쓰는 글자만 받게 할 수 있지만, 앱 안에 넣는 서체를 「자주 쓰는 한글 2,350자」 같은 일부 글자만 남기게 줄이면 안 된다.

- **사용자가 무슨 글자를 칠지 모른다** — 이름·닉네임·댓글에 「똠」「펲」 같은 드문 글자가 나오면, 줄인 서체에 없는 글자만 기기 기본 서체로 그려져 한 낱말 안에서 서체가 섞인다.
- 그래서 한글 11,172자를 모두 담은 파일을 넣는다. 줄여도 되는 것은 **쓰지 않는 문자권**(예: 한자·일본어 글자가 함께 든 서체에서 한자·일본어 부분)뿐이고, 그것도 다국어를 늘릴 때 다시 넣어야 하니 크기가 정말 문제일 때만 한다.

### 4.3 pubspec.yaml 등록

```yaml
flutter:
  fonts:
    - family: Pretendard            # foundation.dart의 FoundationType.family와 글자 하나까지 같게
      fonts:
        - asset: assets/fonts/PretendardVariable.ttf   # 가변 서체면 파일 하나
    # 굵기별 파일이면:
    # - family: Pretendard
    #   fonts:
    #     - asset: assets/fonts/Pretendard-Regular.otf
    #       weight: 400
    #     - asset: assets/fonts/Pretendard-Medium.otf
    #       weight: 500
    #     - asset: assets/fonts/Pretendard-Bold.otf
    #       weight: 700
```

- **`weight`는 파일 이름에서 저절로 읽지 않는다** — 굵기별 파일이면 파일마다 `weight`를 적는다. 빠뜨리면 모든 파일이 400으로 들어가 굵기가 안 바뀐다.
- **서체 허가 문서도 저장소에 둔다** — `assets/fonts/` 안에 허가 문서(`OFL.txt` 등)를 함께 둔다.
- **서체 이름 예시(Pretendard)는 자리표시자다** — 실제 서체는 브리프 「4. 확정 브랜드 자산」의 서체 행이 정한다.

### 4.4 제목 서체 후보를 비교할 때

idea-to-mvp 2-3 개성 입히기에서 제목 서체 후보를 앱 안에서 나란히 볼 때의 규칙이다.

- **후보 서체도 `pubspec.yaml`에 등록해야 비교안에서 보인다** — 비교안은 판 토큰 파일(`lib/core/design/drafts/{판}.dart`)의 `text:`에서 `AppTextStyles`의 정한 글자 이름에 후보의 `fontFamily`를 줄 뿐이라, 파일과 등록 줄이 앱에 이미 있어야 그려진다. 그래서 `assets/fonts/`와 `pubspec.yaml`(본 파일)에 비교하는 동안만 후보가 들어간다.
- **한글 글자 수를 먼저 센다** — 후보를 넣기 전에 서체 파일의 한글 글자가 11,172자 다 있는지 센다(§4.2). 일부 디스플레이 서체는 2,350자뿐이라, 모자라면 후보로 쓰지 않는다. 후보 하나가 MB 단위로 개발용 앱을 키우므로 크기도 같이 적는다.
- **지금 서체가 바닥이다** — 서체를 바꾸고 싶으면 대담판이 후보 하나를 지금 서체와 나란히 보인다. 새 파일은 하나만 들어간다. 지금 서체가 제목에도 쓰이던 것이 아니면 후보를 둘로 하고 파일도 둘이다. 서체 파일과 `pubspec.yaml` 등록 줄을 넣는 것은 대담판 에이전트만이다 — 혁신판·파격판은 대담판이 고른 서체를 이어받고 새로 넣지 않는다.
- **고르지 않은 후보는 3단계 화면 대조가 끝날 때 파일(`assets/fonts/`)과 `pubspec.yaml` 등록 줄을 지운다** — 실서비스 앱에 나가기 전에 지워야 앱 크기가 커진 채 나가지 않는다. 고른 서체는 `FoundationType.titleFamily`에 이름을 두고 이 문서 §3의 자리에 앉힌다.

## 5. 마무리 체크 3가지

1. **서체 이름이 세 곳에서 같다** — `pubspec.yaml`의 `family`, `foundation.dart`의 서체 이름, (있다면) 다른 곳에서 부르는 이름. 하나라도 다르면 Flutter는 오류 없이 기기 기본 서체로 그린다 — 눈으로만 발견된다.
2. **쓰는 굵기와 넣은 굵기가 같다** — 2층 글자 단계와 화면이 쓰는 `FontWeight`(400·500·700 등)가 모두 넣은 파일(또는 가변 서체의 굵기 범위) 안에 있다.
3. **서체 정의는 한곳에 모은다** — 서체 이름은 `foundation.dart`에만, 파일 목록은 `pubspec.yaml`에만. 화면이나 부품에 `fontFamily: '…'`를 직접 쓰지 않는다.

## 6. 필수 관문 — 산출물로 검증한다

**서체를 새로 넣거나 바꾸는 작업은 아래 세 가지를 전부 통과해야 끝난 것이다.** 이건 화면을 눈으로 보는 검증이 아니라 파일과 빌드 결과를 확인하는 검증이라, 에이전트가 직접 끝까지 확인한다. 사람한테 "확인해 주세요"로 넘기지 않는다. (하네스의 「화면 검증은 사람 몫」 원칙은 화면을 보는 일이라 이 관문에 해당하지 않는다. 글자 모양이 마음에 드는지는 따로 사람이 본다.)

Flutter 명령(`flutter build` 등)은 프로젝트 AGENTS.md가 정한 판 고정 도구를 앞에 붙여 부른다.

**(1) 등록한 파일이 실제로 있는가**

```bash
grep -E '^[[:space:]]*- asset: assets/fonts/' pubspec.yaml | sed -E 's/.*asset: //' | while read -r f; do
  [ -f "$f" ] && echo "있음: $f" || echo "없음: $f"; done
```

「없음」이 하나라도 나오면 빌드가 실패하거나(경로 오류) 그 굵기가 빠진다.

**(2) 서체가 앱 안에 들어갔는가** — 디버그 빌드를 한 번 돌린 뒤, 빌드 결과의 자산 목록에 서체가 있는지 본다.

```bash
grep -o '"assets/fonts/[^"]*"' build/app/intermediates/flutter/*/flutter_assets/FontManifest.json 2>/dev/null \
  || find build -name FontManifest.json -exec grep -o '"assets/fonts/[^"]*"' {} +
```

넣은 파일 경로가 나와야 한다. 아무것도 안 나오면 `pubspec.yaml`의 들여쓰기(`fonts:`가 `flutter:` 아래에 있는지)를 먼저 본다. 빌드 결과 폴더 모양은 Flutter 판마다 다를 수 있어 두 번째 줄로 넓게 찾는다.

**(3) 앱 크기가 얼마나 늘었는가** — 서체를 넣기 전과 뒤의 크기를 비교한다. 크기 분석 기능(`flutter build apk --analyze-size` 같은 꼴 — 정확한 인자는 그 판의 문서로)을 쓰면 무엇이 얼마를 차지하는지 나온다. 서체 하나가 몇 MB를 넘으면 §4.1의 다른 파일 갈래(가변 ↔ 굵기별)와 비교해 작은 쪽을 고르고, 보고에 늘어난 크기를 적는다.

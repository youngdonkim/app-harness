# code-cleanup — 바뀐 코드만 한 번 정리하기

메인 세션에서 돈다(fork 아님) — 검토·반영을 서브 에이전트에게 맡기고, 그 사이 판단과 커밋은 메인이 한다.

**하는 일은 셋이다.** ① 검토 에이전트 하나가 바뀐 파일을 한 번 읽고 보고서 하나를 쓴다 → ② 반영 에이전트 하나가 화면 동작을 바꾸지 않는 것만 고친다 → ③ 메인이 반영을 커밋하면서 그 커밋에 정리 표시 제목을 붙인다. 같은 코드를 여러 에이전트가 따로 읽지 않게 해서 싸게, 표시는 반영이 실제로 끝난 뒤에만 붙여서 확실하게 한다.

## 호출 인자

이번 호출의 인자: **$ARGUMENTS**

비어 있으면 인자 없이 호출된 것. 부른 쪽이 「done-task에서」·「3단계 끝」처럼 어디서 불렀는지 적어 줄 수 있다 — 마무리 보고에만 쓴다.

## 정리 표시 커밋

- 제목은 **`chore: 코드 정리 반영 — <한 줄 요약>`** 하나다. 고칠 것이 없었으면 `chore: 코드 정리 반영 — 고칠 것 없음`.
- **이 커밋은 ③에서 메인만 만든다.** 검토가 끝나기 전, 반영이 끝나기 전에는 만들지 않는다. `auto-wip-commit` 훅이 남기는 `wip: …` 커밋은 제목이 무엇이든 표시가 아니다.
- `ship-task` §1.5 관문은 이 제목을 아래 정규식으로 찾는다. 제목을 바꾸면 그쪽도 같이 바꾼다.
  ```bash
  git log origin/main..HEAD --no-merges --format='%H %s' | grep -E '^[0-9a-f]+ chore: 코드 정리 반영( |$)' | head -1
  ```

## 절차

### 1. 자리 확인

`git branch --show-current`. main이거나 비어 있으면(detached HEAD) 멈춘다 — 정리 커밋은 작업 브랜치에만 쌓는다.

### 2. 대상 파일 — 지난 정리 뒤 바뀐 코드 파일만

```bash
git fetch -q origin main 2>/dev/null || true
# 기준점: 이 브랜치의 마지막 정리 표시 커밋. 없으면 main에서 갈라진 지점.
base=$(git log origin/main..HEAD --no-merges --format='%H %s' | grep -E '^[0-9a-f]+ chore: 코드 정리 반영( |$)' | head -1 | cut -d' ' -f1)
[ -n "$base" ] || base=$(git merge-base origin/main HEAD 2>/dev/null || git merge-base main HEAD)
# 기준점 뒤 이 브랜치가 직접 고친 파일(합치기 커밋으로 들어온 남의 변경은 뺀다) + 아직 커밋 안 된 변경
{ git log --no-merges --format= --name-only "$base"..HEAD -- lib test functions/src; git status --porcelain --untracked-files=all -- lib test functions/src | sed -E 's/^...//'; } \
  | sed -E 's/.* -> //' | sort -u | grep -vE '^lib/dev/|\.g\.dart$|\.freezed\.dart$|/firebase_options_[^/]*\.dart$|/app_localizations[^/]*\.dart$|\.(ico|png|jpe?g|webp|gif|svg)$' | while IFS= read -r f; do [ -f "$f" ] && printf '%s\n' "$f"; done
```

- **대상은 Dart(`lib/`·`test/`)와 TypeScript(`functions/src/`)다.** 폴더가 아직 없는 단계(서버 함수가 없는 3단계 등)면 있는 폴더만 읽는다.
- **생성 파일과 개발용 도구, 그림은 대상이 아니다** — `lib/dev/`(목업 캔버스·비교안 같은 개발용 도구), 만들어지는 파일(`*.g.dart`·`*.freezed.dart`·`firebase_options_*.dart`·`app_localizations*.dart`)은 정리하지 않는다. 생성 파일은 `build_runner`와 다국어 생성 명령이 다시 만들어 덮어쓰고, 개발용 도구는 실서비스에 안 들어간다. 그림 파일(`.ico`·`.png`·`.jpg`·`.webp`·`.gif`·`.svg`)은 코드가 아니라 뺀다. 다국어 문구 파일(`.arb`)은 코드 정리가 아니라 `ux-writing-reviewer`의 몫이라 목록에 들어와도 읽기만 한다. 프로젝트의 폴더 이름이 다르면 그 이름으로 바꿔 거른다.
- **목록이 비었으면** 정리할 코드가 없다 — 표시 커밋 없이 「지난 정리 뒤 바뀐 코드가 없습니다」로 끝낸다.
- **자잘하면 건너뛴다** — `git diff "$base" --stat -- <목록>` 기준 주석·문구 몇 줄뿐이고 로직이 없으면 「자잘해 건너뜀」으로 끝낸다. 표시 커밋을 남기지 않으니, 다음 정리 때 이 파일들도 다시 대상에 든다.

### 4. 메인이 거른다

보고서에서 **「화면 동작이 바뀌나」가 「예」나 「모름」인 항목은 뺀다** — 화면이 어떻게 보이고 움직이는지는 사람이 확인한 상태라, 정리가 그걸 바꾸면 사람이 본 코드와 main에 들어가는 코드가 달라진다. 뺀 항목 중 고칠 만한 것은 마무리 보고에 「사람이 정할 것」으로 남긴다.

- **검토가 따로 적은 「눈에 띈 버그」는 반영 목록에 넣지 않는다** — 버그를 고치면 화면 동작이 바뀐다. 마무리 보고의 「사람이 정할 것」에 그대로 남겨 사용자가 정한다.

- **남은 항목이 없으면** 반영 없이 표시만 남긴다 — 검토가 끝났다는 기록이다.
  ```bash
  git commit --allow-empty -m "chore: 코드 정리 반영 — 고칠 것 없음"
  ```
  그리고 6으로.

### 6. 커밋 — 반영이 끝난 뒤에만 표시

반영 보고를 받으면 메인이:

1. `git status --porcelain`에 `.env*`·키 파일이 보이면 add 전에 멈추고 보고한다.
2. `git diff --stat`으로 고친 파일이 2의 목록 안인지 본다. 목록 밖이 많이 바뀌었으면 미심쩍은 곳만 골라 읽는다.
3. 검사가 실패로 끝났으면 커밋하지 않는다 — 반영 에이전트에게 고치게 하거나(같은 실패 2회면 멈춤), 그 항목을 되돌린다.
4. 커밋한다. `--allow-empty`는 반영 도중 턴이 끝나 훅이 변경을 이미 `wip:`으로 담아 둔 경우에도 표시가 남게 하려는 것이다.
   ```bash
   git add -A && git commit --allow-empty -m "chore: 코드 정리 반영 — <한 줄 요약>"
   ```

## 한 대화 안에 안 끝날 때 (큰 변경)

2의 목록이 크면(파일 40개 넘게, 바뀐 줄 수천 줄) 한 턴에 끝내려 하지 않는다. idea-to-mvp의 3단계 끝 정리는 2·3단계 코드 전체가 대상이라 대개 여기에 든다 — 그때는 아래 묶음 나누기가 기본이다.

- **비교안 전용 파일은 대상에서 뺀다** — `lib/core/design/drafts.dart`·`lib/core/design/drafts/`·`lib/dev/drafts/`·`test/draft_checks/`(2-2·2-3이 비교안만을 위해 만든 자리)는 3단계에서 지워질 파일이라 검토하지 않는다. 2단계 끝에서 불려도 같다.
- **파일이 40개를 넘으면 검토를 폴더 묶음으로 나눈다** — 한 묶음 20~30개, 묶음마다 검토 에이전트 하나, 같은 파일이 두 묶음에 들지 않게. 보고서는 메인이 합친다.
- 검토·반영 에이전트를 백그라운드로 띄우고 턴을 끝내도 된다. 알림이 오면 다음 턴에 4·6을 잇는다.
- **표시 커밋(6)이 생긴 다음 턴에 합치기(ship)로 넘어가도 된다** — done-task에서 불렸으면 그 턴에 `ship-task`를 부른다.
- 중간에 끊겨 표시 커밋이 없으면 다음에 부를 때 2부터 다시 한다(검토만 다시 든다).

## 마무리 보고

~입니다 체로 짧게: 대상 파일 수 · 반영한 것 · 건너뛴 것(화면 동작이 바뀌어서 등 — 사람이 정할 것이면 그렇게) · 검사 결과 · 표시 커밋 제목. 부른 쪽이 done-task면 이 보고를 ship 보고 앞에 한 줄로 줄여 붙인다.

## 안 하는 것

- ❌ 검토 전·반영 전 표시 커밋 — 표시는 6에서만, 고칠 것이 없을 때는 4의 빈 커밋만
- ❌ 같은 파일을 여러 에이전트가 따로 읽기 — 관점을 갈래로 나누지 않고 한 보고서로
- ❌ 화면 동작이 바뀌는 정리 — 사람이 정할 것으로 넘긴다
- ❌ 지난 정리 앞의 파일을 다시 검토 — 기준점은 마지막 표시 커밋
